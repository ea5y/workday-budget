# 工作日预算器 · 最新需求（v1）

> 2026-11-04 · 本文取代此前的界面与范围描述，口径以 `AGENTS.md` §3 为准

## 0. 形态

| 项 | 决定 |
|---|---|
| 宿主 | **DSH 插件**（Cordis bundle），非独立应用 |
| 界面 | **全屏仪表盘**：左侧栏一个入口（如「用量」）→ 主面板铺满内容区 |
| 平台 | 公司机 Windows，单机 |
| 明确放弃 | 侧栏窄面板（v0.3）、系统托盘（v0.4）、手机端 |

## 1. 计量（P0）

**两个数据源，必须分开算、合并显示：**

| 源 | 取数 | 覆盖率 | 是否校准 |
|---|---|---|---|
| A · DSH 会话 | `ctx.sessionQuery` 的 `assistant/message` | 100% | **不校准** |
| B · Claude Code | `~/.claude/projects/**.jsonl` | ~88% | **×1.14** |

规则：

1. 按 `message.id` 去重（实测重复 2.3 倍）；
2. `timestamp` 是 UTC 但不带时区 → 按 UTC 解析后 +8 小时；
3. 计价（元/百万 token）：

| 项目 | 谷时 | 峰时 |
|---|---|---|
| 缓存命中 | ¥0.02 | ¥0.04 |
| 未命中输入 | ¥1.00 | ¥2.00 |
| 输出 | ¥4.00 | ¥8.00 |

4. 峰时 = 北京时间工作日 09:00–12:00、14:00–18:00，其余谷时；
5. `cache_creation` 忽略（DeepSeek 不收缓存写费）；
6. 页面必须同时显示**原始**与**校准后**两个数，并标注哪部分来自哪个源。

## 2. 预算与硬顶（P0）

- 日预算默认 **¥10**，可配；
- 状态机：`NORMAL(<70%) → WARN(70–90%) → WINDDOWN(90–100%) → LOCKED(≥100%)`；
- **到 100% 立即停**，无论交付是否完成；
- **收尾豁免**：LOCKED 后仍可提交/测试/写交接，独立 ¥0.50 额度；
- **二级上限**：默认 ¥20、默认关闭；需满足前置条件（距承诺交付日 ≤ 2 天 且 剩余工作量 > 1 个标准日）+ 必填理由 + 每月 ≤ 4 次；
- **不借贷、不预支**，今日额度不可从明日借用。

## 3. 时间与结余（P1）

- 时间当量：**1 元 = 48 分钟**；
- `今日收益 = 标准工作日 − 实际墙钟`；
- 结余**不结转成额度**，只兑换为时间；
- 收工生成摘要 + 凭证码（跨机用，v2 才启用）。

## 4. 交付与排期（v1 不做，设计保留）

交付项登记、顺延队列、积压闸门（> 2 个标准日强制重谈）、溢出报告（预算/实际/完成项/预测日 vs 承诺日）、排期计算器（P50/P80 + 加预算/减范围/改日期三杠杆）。

## 5. 资讯简报（v2）

关注源可配（DeepSeek / Codex / Claude Code / CC Switch），分级 P0/P1，≤ 5 条 / ≤ 300 字 / 2 分钟，**空报告合法**。

## 6. 双机（v2）

公司机只跑 `work` 账本，Mac 只跑 `personal` 账本，物理隔离；只传日汇总，不传内容；收工凭证手工录码。

## 7. 验收标准

- **AC-1** 用 10-27~10-31 五天账单回归，合计误差 ≤ ±8%（当前 −12.1% 原始 / 校准后 ±7%）；
- **AC-2** 到 ¥10 时，下一次模型请求被拒（hook 或等价机制）；
- **AC-3** 面板同时显示 DSH 与 Claude Code 两个来源，且校准只作用于后者的；
- **AC-4** 页面首次渲染 < 500ms，刷新 < 200ms；
- **AC-5** 断网可用（全部本地计算）；
- **AC-6** 插件卸载后无残留进程与定时任务。

## 8. 明确不做

手机端 · 团队版/管理者视图 · 排行榜 · 游戏化 · 键鼠与窗口标题采集 · 模型路由 · 自动"再干一会儿"

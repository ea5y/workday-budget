## 0. 摘要

把「今天的工作」当成一笔 **¥10 的硬预算**来经营：

```
工作花费   = Claude Code 当日用量 × 1.14 校准
剩余额度   = 10 − 工作花费
状态       = NORMAL / WARN / WINDDOWN / LOCKED
到 100%    = 下一次模型请求被 hook 拒绝
收工收益   = 标准工作日 − 实际墙钟；结余按 1 元 = 48 分钟兑换为时间
```

三条硬规则：

1. **预算只约束 Claude Code**。DSH 的消耗单独记为 `tooling` 账本，**不计入 ¥10**，只在仪表盘展示。
2. **硬顶必须发生在模型请求之前**，由 Claude Code hooks 执行，不依赖面板是否打开。
3. **算账引擎独立于 DSH**。DSH 插件是表盘；DSH 关着时，Claude Code 的预算和硬顶仍然有效。

## 1. 背景与问题

### 1.1 三个场景

| # | 场景 | 需求 |
|---|---|---|
| S1 | AI 编程限额 | 一天最多 ¥10；到上限必须停，无论任务是否完成；上限可配 |
| S2 | AI 资讯 | 每天知道有没有大事（Codex / Claude Code / DeepSeek / CC Switch），v2 再做 |
| S3 | 时间再投资 | 半天干完就算一天干完；省下的时间投给自己的事 |

### 1.2 真实负载在哪

- 日常工作 90% 以上发生在 **Claude Code + CC Switch + DeepSeek** 的终端工作流里；
- DSH 目前用于插件开发、探索和部分自动化，是 **工具成本**，不是公司交付的主账本；
- 因此：**Claude Code 计入预算；DSH 只展示，不计入预算**。这是 v1.0 的明确决策。

### 1.3 为什么不能只做 DSH 插件

旧文档已经指出：只做 DSH 面板 = 表盘接不上发动机。DSH 插件可以负责「看」和「设置」，但 **算账和阻断必须独立运行**，否则：

- DSH 没开时，Claude Code 的花费没人记；
- 到 100% 时，hook 读不到最新 `state.json`，拦不住下一次请求；
- 面板与 hook 各算一套账，数字对不上。

v1.0 的形态因此分成两层：

- **产品入口**：DSH 左栏 → 全屏仪表盘；
- **运行时核心**：本地 `wb` 引擎（无 UI、无端口、用户级权限），负责记账、状态和 hook 判定。

## 2. 产品定位

**是什么**

- 一个「把工作当成有硬上限的预算」的本地工具；
- 一个 Claude Code 的花费账本 + 硬顶 + 状态栏 + 收工结算；
- 一个 DSH 全屏仪表盘，用来看今日预算、来源构成、明细和设置；
- 一个把结余兑换成「自由时间」的收益框架。

**不是什么**

- 不是通用 Token 统计大盘；
- 不是团队效能工具、管理者视图、排行榜；
- 不是模型路由器，不自动切便宜模型；
- 不是工时监控，不采集键鼠、窗口标题、截屏；
- 不是 DSH 专属插件：DSH 只是 v1 的 UI 宿主；
- 不做手机端、不做托盘、不做窄侧栏。

**成功的样子**

- Claude Code 状态栏常驻 `work 4.2/10`，70% 变黄、90% 变红；
- 到 ¥10 时，下一次提交被拒绝，并给出一行可执行提示；
- 打开 DSH 仪表盘，3 秒内看清：今天花了多少、花在哪、几点必须停、还能换多少自由时间；
- 周维度能看到「为公司 / 为自己」的时间与金额，而不是每天盯数字焦虑。

## 3. 设计原则

| # | 原则 | 含义 |
|---|---|---|
| P1 | 预算即硬顶 | 到 100% 立刻停，没干完也停 |
| P2 | 溢出归排期，不归人品 | v1.1 起记录为排期偏差，不扣分、不连续失败 |
| P3 | 日期是算出来的 | 范围 ÷ 日预算 = 日期；日期不是拍出来的承诺 |
| P4 | 紧急通道必须昂贵且受限 | 二级上限有理由、配额、留痕 |
| P5 | 计量必须经得起自欺 | 数字来自日志与账单，不来自手填 |
| P6 | 空报告是合法输出 | 没有 P0 资讯就说没有（v2） |
| P7 | 账本按设备硬隔离 | 公司机只跑 `work`；`personal` 不上公司机（v2） |
| P8 | 分类由项目决定 | 项目路径 → 类别；不靠窗口标题 |
| P9 | 终端优先 | 状态栏与 hook 比面板更常被看见 |
| P10 | 收益框架优先 | 主视觉是「还剩多少自由时间」，不是「花了多少钱」 |

## 4. 术语

| 术语 | 定义 |
|---|---|
| **工作账本 `work`** | Claude Code 的消耗，计入 ¥10 日预算 |
| **工具账本 `tooling`** | DSH 的消耗，不计入预算，只展示与复盘 |
| **日预算** | 默认 ¥10，硬性；改当日预算需二次确认并留痕 |
| **硬顶** | 达到 100% 后，hook 拒绝新的模型请求 |
| **收尾豁免** | LOCKED 后仍可提交/测试/写交接的独立 ¥0.50 额度 |
| **二级上限** | 默认 ¥20、默认关闭；手动启用 + 理由 + 每月 ≤ 4 次 |
| **校准系数** | Claude Code 日志只覆盖约 88% 真实花费，默认 ×1.14；DSH 不校准 |
| **来源 `source`** | `claude` / `dsh`；每条用量必须带来源 |
| **时间当量** | 默认 1 元 = 48 分钟 |
| **标准工作日** | 默认 8 小时，可配 |
| **今日收益** | `max(0, 标准工作日 − 实际墙钟)` |
| **收工凭证** | v2 可选项；收工时的一行短码仅用于后续跨机，不在 v1.0 范围 |

### 5.1 做

| 模块 | 内容 |
|---|---|
| 计量 | Claude Code JSONL 采集、去重、计价、×1.14 校准；DSH 用量采集（只展示） |

| 预算 | ¥10 日预算、状态机、收尾豁免、简化二级上限 |

### 5.2 不做（v1）

- 交付项登记、顺延队列、积压闸门、溢出报告（v1.1）
- 排期计算（P50/P80）与承诺日（v1.2）
- 资讯简报（v2）
- 双机双账本、个人时间块、收工凭证跨机（v2）
- 手机端、托盘、窄侧栏、独立桌面应用
- CPU / 系统监控
- 团队版、管理者视图、排行榜、游戏化
- 模型路由、自动切换便宜模型

### 5.3 关键边界

- **DSH 不计入 ¥10**；仪表盘可以显示「工作 + 工具」的合计，但预算进度只用工作账本。
- **DSH 不设硬顶**。如果以后 DSH 成为主要工作负载，再单开 `tooling` 上限（v2 讨论）。
- **v1 不判断交付是否完成**。因此只实现预算状态；`DONE` / `SPILL` 的交付判定在 v1.1 引入交付项后启用。

## 6. 计量

### 6.1 两个数据源

| 源 | 取数 | 账本 | 是否计入 ¥10 | 校准 | 覆盖率 |
|---|---|---|---|---|---|
| A · Claude Code | `~/.claude/projects/**/*.jsonl` | `work` | **是** | **×1.14** | 约 88% |
| B · DSH | `ctx.sessionQuery` 的 `assistant/message` | `tooling` | **否** | **×1.00** | 按 100% 处理 |

**合并显示规则**

```
display_total = work_spent + tooling_spent
budget_used  = work_spent
budget_pct   = work_spent / cap
```

页面必须同时给出 `work` 与 `tooling` 的分项，不能只给一个合计；合计只用于“知道总共花了多少”，不参与预算判定。

### 6.2 计价

价格（元 / 百万 token）：

| 项目 | 谷时 | 峰时 |
|---|---|---|
| 缓存命中 | ¥0.02 | ¥0.04 |
| 未命中输入 | ¥1.00 | ¥2.00 |
| 输出 | ¥4.00 | ¥8.00 |

规则：

1. 峰时 = 北京时间工作日 **09:00–12:00、14:00–18:00**；其余谷时；法定节假日按配置的 `holidays` 视为谷时。
2. `cache_creation_input_tokens` 忽略：DeepSeek 不单独收缓存写费。
3. 非主力模型（如 pro）只提示「单价约为 flash 的 N 倍」，**不改预算数值、不自动折算**。
4. 价格表按模型分档、带 `effective_from`，允许用户覆盖（中转站价格）。
5. 模型别名映射：`deepseek-flash` / `deepseek-v4-flash` 按 Flash 计价。

### 6.3 去重与时间

| 源 | 去重键 | 时间处理 |
|---|---|---|
| Claude Code | `(source='claude', message.id)`，跨文件去重 | `timestamp` 是 UTC 但不带时区 → 按 UTC 解析后 +8 小时 |
| DSH | `(source='dsh', sessionId, message.id)` | `event.time` 是 epoch ms → 按 Asia/Shanghai 切日 |

同一响应平均重复约 2.3 倍；重复扫描不得重复计数。

### 6.4 采集与性能

**Claude Code**

- 递归扫描 `~/.claude/projects/**/*.jsonl`；当前约 29 个文件、2.3 万行，去重约 1.3 万条；
- 增量扫描：记录每个文件的 `offset + mtime`，只读新增行；全量重扫作为修复手段；
- 坏行、缺字段、未知模型：计数并在 `wb doctor` 中可见，不静默丢弃；
- 单次全量扫描应 < 2s；增量扫描 < 200ms；hook 只读 `state.json`，< 100ms。

**DSH**

- 通过 `ctx.sessionQuery.listSessions()` + `readSession()` 读取；
- 只取 `assistant/message` 的 `usage`，按 `message.id` 去重；
- live session 按事件 revision 增量刷新，历史 session 进程内缓存；
- 只用于展示，不写 `work` 账本。

### 6.5 校准

- Claude Code：`cost_calibrated = cost_raw × calibration`，默认 `1.14`；
- DSH：`cost_calibrated = cost_raw`（不校准）；
- 页面必须同时显示「原始 / 校准后」，并标注校准只作用于 Claude Code；
- 日终可录入平台账单，自动重算校准系数（v1 提供手动入口，自动拟合 v1.1）。

### 6.6 准确性验收

以 `tools/usage-export/` 的五天账单为黄金样本（归档在原始工作区，不随仓库提交）：

| 日期 | 请求 | 账单 |
|---|---|---|
| 10-27 | 285 | ¥9.2931 |
| 10-28 | 401 | ¥9.6441 |
| 10-29 | 694 | ¥14.5311 |
| 10-30 | 577 | ¥15.4354 |
| 10-31 | 1700 | ¥19.2297 |
| 合计 | 3657 | ¥68.1344 |

当前 `wb-core` 原始合计 ¥59.89（−12.1%），×1.14 后约 ¥68.27，与账单偏差约 +0.2%。任何计价改动必须重跑这组样本。

### 6.7 隐私

- 全部本地计算，不联网、不上传；
- 只读取 token 用量、模型、时间、项目路径；**不读取/不存储 prompt 正文**；
- 账本与状态文件权限为用户级；
- DSH 插件的本地路由只允许 loopback 访问（v1 若使用路由）。

## 7. 预算与硬顶

### 7.1 日预算

- 默认 ¥10，可配；
- 修改当日预算需要二次确认，并写入 `budget_change` 事件；
- 不借贷、不预支：今日额度不能从明日借用，也不能提前消耗。

### 7.2 状态机

| 状态 | 触发 | 允许的动作 | 提示 |
|---|---|---|---|
| `NORMAL` | < 70% | 全部 | 无 |
| `WARN` | 70–90% | 全部；新任务需确认预估 | “还剩 ¥X，建议先砍范围” |
| `WINDDOWN` | 90–100% | 仅收尾与已开任务修补 | “进入收尾，不再开新任务” |
| `LOCKED` | ≥ 100% | 收尾豁免（¥0.50）+ 二级上限入口 | “今天的额度用完了” |
| `TIER2` | 二级启用后 < 90% | 全部 | “二级已启用，剩余 ¥X” |
| `TIER2_WARN` | 二级下 ≥ 90% | 仅收尾与修补 | “二级快用完了” |
| `TIER2_LOCKED` | 二级下 ≥ 100% | 仅收尾 | “二级也用完了” |

`DONE` / `SPILL` / `SPILL_HARD` 依赖交付项，v1 不实现；v1.1 引入交付项后启用。

### 7.3 硬顶（v1 必须）

**执行点：Claude Code hooks**

- `UserPromptSubmit`：预算足够 → exit 0；LOCKED / 二级用尽 / 收尾用尽 → exit 2，输出单行可执行提示；
- `PreToolUse`：LOCKED 后阻断会继续产生模型消耗的工具调用；只读或收尾白名单内的操作放行；
- 不杀掉正在运行的工具，不修改已提交的改动；
- 提示示例：`work 10.02/10 · 今日额度已用完，只剩收尾；输入 /wrapup 开启 ¥0.50 收尾额度`。

**状态栏**

- `wb statusline` 输出单行：`work 5.4/10`；70% 黄、90% 红、LOCKED 红底；
- 刷新 < 200ms；不阻塞输入。

**hooks 安装/卸载**

- `wb hooks install`：写入用户级 `~/.claude/settings.json`，带 `workbuddy` 标记；先备份，幂等；
- `wb hooks uninstall`：只移除自己写入的条目，保留用户其他 hooks；
- `wb hooks status`：显示已安装、路径、最近一次 exit 2 时间；
- 面板设置页提供「安装 / 卸载 / 检查」入口，操作前二次确认。

**状态过期**

- `state.json` 超过 5 分钟未更新：hook 先尝试一次有界增量刷新；
- 刷新失败或仍过期：**放行并显示 STALE 警告**，不静默阻断；`wb doctor` 给出修复建议；
- 这是为了避免「记账进程挂了 → 人被永久锁死」；STALE 必须在状态栏与面板可见。

### 7.4 收尾豁免

- LOCKED 后，用户点击「开始收尾」或执行 `wb wrapup`，开启独立 **¥0.50 / 30 分钟**额度；
- 收尾期间允许提交、测试、写交接摘要；每次请求计入 `wrapup_spent`；
- 用尽后只允许零 token 本地操作；
- 收尾结束自动生成收工摘要；未用完的收尾额度不结转。

### 7.5 二级上限（v1 简化版）

- 默认 ¥20、默认关闭；
- 启用条件（v1）：**手动启用 + 必填一句理由 + 二次确认 + 每个自然月 ≤ 4 次**；
- 启用后 18 元告警、20 元锁定；
- 记录 `tier2_use { date, reason, started_at, ended_at, resulted_in_spill }`；
- 旧文档的「距承诺交付日 ≤ 2 天 且 剩余工作量 > 1 个标准日」依赖交付/排期数据，v1 不做；完整条件放 v1.2。

## 8. 时间与结算

### 8.1 时间当量

- 默认 **1 元 = 48 分钟**；
- 标准工作日默认 **8 小时**，可配；
- `time_credit = max(0, cap − work_spent) × 48 分钟`；
- `today_gain = max(0, 标准工作日 − 实际墙钟)`；
- 结余**不结转成额度**，只兑换为时间。

### 8.2 开工 / 收工

- 面板提供「开工 / 收工」按钮；CLI 提供 `wb start` / `wb done`；
- v1.0 **只做手动**：不根据首/末请求自动推断，也不弹自动建议；
- 实际墙钟 = 收工 − 开工；跨日只标记，不做两段计费。

> 实现状态（2026-11-04）：手动单段 `start/done/reopen --at` 已做。自动首请求开工、末请求 +5 建议已移出 v1.0，作为 v1.1 可选体验。

### 8.3 收工摘要

- 一行结论：`今天 ¥5.40/10 · 还剩 ¥4.60 · 约 3h41m 自由时间`；
- 明细：请求数、项目 Top 3、模型构成、原始/校准、二级是否启用；
- v1.0 不生成凭证码；凭证码是 v2 的跨机可选项；
- 可复制为 Markdown。

### 8.4 周视图（v1 轻量）

- 近 7 天工作账本柱状图 + 预算线；

## 10. 架构

### 10.1 两层

```
Claude Code ──写──▶ ~/.claude/projects/*.jsonl
                          │ 增量监听
                          ▼
                   ┌─────────────┐
                   │  wb 核心     │  独立进程 / CLI，无 UI、无端口
                   │  算账 + 状态 │
                   └──────┬──────┘
         ┌────────────────┼─────────────────┐
         ▼                ▼                 ▼
   state.json       Claude Code hooks    wb statusline
   （唯一真相）     （UserPromptSubmit /   （work 5.4/10）
                     PreToolUse）
         ▲
         │ 只读
   ┌─────┴──────────────────────────────┐
   │ DSH 插件（UI）                      │
   │  今日预算 / 来源 / 明细 / 7 天 / 设置 │
   │  + DSH tooling 采集（只展示）        │
   └────────────────────────────────────┘
```

### 10.2 只有一个算账者

- `wb` 核心是 **work 账本**的唯一计算者；
- DSH 插件不重新计算 work 预算，只读 `state.json`；
- DSH 的 `tooling` 用量由插件自己采集，只用于展示，不写 work 账本；
- hook 和 statusline 只读 `state.json`，不各自扫描日志。

### 10.3 为什么核心必须独立

- DSH 可能没开，Claude Code 仍在工作；
- hook 必须在 DSH 关闭时仍能拦截；
- 面板刷新失败不能影响硬顶；
- 旧文档的「可一键停用」要求核心可独立停止，而不是藏在 DSH 进程里。

### 10.4 运行形态

- `wb` 为 Node 24+ 的本地 CLI / 常驻 watcher（公司机已具备 Node；Claude Code 本身依赖 Node）；
- 无管理员权限、无端口监听、无系统服务；
- 由用户级启动项或手动 `wb watch` 启动；`wb doctor` 检查是否在跑；
- DSH 插件只负责 UI 和 DSH tooling 采集，不负责 work 账本的存活。

### 10.5 数据流

1. `wb watch` 监听 Claude Code JSONL 增量；
2. 解析、去重、计价、×1.14，写入 `ledger/YYYY-MM.jsonl`；
3. 重算当日 `day_ledger` 与 `state.json`；
4. hook / statusline / DSH 插件读取 `state.json`；
5. DSH 插件另行读取 `ctx.sessionQuery`，生成 `tooling` 展示数据；
6. 仪表盘把两者合并展示，但预算只用 work。

## 12. CLI 与接口

### 12.1 CLI

| 命令 | 作用 | 退出码 |
|---|---|---|
| `wb status` | 今日已花 / 剩余 / 状态 | 0 |
| `wb today` | 今日明细 | 0 |
| `wb log` | 最近请求 | 0 |
| `wb start` | 开工 | 0 |
| `wb done` | 收工 + 摘要 | 0 |
| `wb wrapup` | 开启 ¥0.50 收尾 | 0 |

| `wb statusline` | 单行状态栏 | 0 |
| `wb hooks install/uninstall/status` | hooks 管理 | 0 |
| `wb doctor` | 自检（路径/权限/进程/过期） | 0 / 1 |
| `wb export` | 导出 CSV/Markdown（v1.1） | 0 |

### 12.2 hook 输出契约

- 成功：无输出，exit 0；
- 阻断：**单行**中文提示，exit 2；不得多行、不得刷屏；
- 阻断提示必须包含：当前花费 / 上限 / 下一步动作；
- 不得修改用户输入、不得杀进程、不得写会话内容。

### 12.3 DSH 插件

- 左栏 `sidebar.panellist` 入口，id `workday-budget`，label「预算」；
- `main` keyed slot 渲染全屏仪表盘；
- 读取 `state.json`（Host 文件读取）与 `ctx.sessionQuery`（tooling）；
- 设置写入 `config.json` 需二次确认；
- hooks 安装/卸载通过调用 `wb hooks` 完成；
- 插件不负责 work 账本计算。

## 14. 验收标准（v1）

- **AC-1** 用 10-27~10-31 五天账单回归：原始合计 −12.1%，×1.14 后与账单偏差 ≤ ±8%。
- **AC-2** work 花费达到 ¥10 时，下一次 Claude Code 提交被 hook 拒绝（exit 2），输出单行提示；已运行工具不受影响。
- **AC-3** 仪表盘同时显示 `work` 与 `tooling`：work 计入预算且 ×1.14；tooling 不计入且不校准；合计只作展示。
- **AC-4** 全屏仪表盘首次渲染 < 500ms，刷新 < 200ms（使用缓存状态）。
- **AC-5** 断网时全部功能可用。
- **AC-6** `wb hooks install` / `uninstall` 幂等，卸载后 `~/.claude/settings.json` 无残留条目，无后台进程。
- **AC-7** LOCKED 后开启收尾：¥0.50 内可提交/测试/写交接；用尽后下一次请求被拒。
- **AC-8** 二级上限启用后上限 ¥20，18 元告警、20 元锁定；理由、时间、月度次数留痕。
- **AC-9** 重复扫描不重复计数；删除 `state.json` 后可由 ledger 重建。
- **AC-10** 收工生成摘要：花费、剩余、时间当量、今日收益；凭证码移出 v1.0。
- **AC-11** 近 7 天视图正确区分 work 与 tooling；work 柱状图有预算线。
- **AC-12** DSH 消耗不改变 work 预算状态（构造 DSH-only 消耗，预算仍为 0）。
- **AC-13** 插件卸载后无残留路由/进程；`wb` 可独立运行。

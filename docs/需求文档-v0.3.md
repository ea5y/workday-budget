## 0. 摘要

把「今天的工作」当成一笔**有硬上限的预算**来经营：花完就收工，干完也收工。省下的时间强制转投到自己的事业；没干完的顺延，**这不是个人的债，是排期的问题**。

三条核心公式：

```
交付日期   = 范围 ÷ 日预算          ← 日期是算出来的结果，不是拍出来的承诺
今日收工   = min(预算用尽, 交付完成)  ← 两种结局都算正常收工，只是结算不同
今日收益   = 标准工作日 − 实际墙钟    ← 真正的产出是"多出来的半天"
```

一层底座 + 三个环：

- **底座（计量内核）**：独立于任何宿主的本地账本与策略引擎，跑在每台机器上；
- **计量环**：Claude Code / DSH 的消耗折算成钱，逐日累计，可审计；
- **硬顶环**：到 100% 立即停，只剩收尾；继续工作唯一合法通道是二级上限；
- **排期环**：范围与预算决定日期；算出来晚于期望就摆三个杠杆，而不是加班；
- **再投资环**：收工即开启个人时间块，单独记账。

一句话价值：**让时间有价格，让结余有去处，让延期有据可查。**

## 1. 背景

### 1.1 三个场景

| # | 场景 | 用户原话（意译） |
|---|---|---|
| S1 | AI 编程限额 | 一天用在 AI 编程上的钱最多 10 块，超过必须停止；上限可配；**即使没干完也停** |
| S2 | AI 资讯 | 每天要知道有没有大事，尤其 Codex / Claude Code / DeepSeek / CC Switch；关注对象可指定 |
| S3 | 时间再投资 | 半天干完就算一天干完，省下的半天投给自己的自媒体 |

### 1.2 共同结构

**给一类稀缺资源划边界，再把省下的容量转投到别处。**

| 场景 | 被约束的资源 | 边界 | 释放出的容量 | 去向 |
|---|---|---|---|---|
| S1 | AI 编程消耗（钱） | 日预算 10 元，硬性 | 未花完的额度 | 兑换成时间 |
| S2 | 信息焦虑（注意力） | 每天 2 分钟 | 漫无目的刷资讯的时间 | 回到工作或个人 |
| S3 | 工作时长 | 预算用尽或交付完成 | 半天时间 | 个人事业 |

### 1.3 真正要解决的问题

不是"省钱"，也不是"看新闻"。是：**一天的时间没有标价，所以会被无意识地稀释**——上班时用加班兜底，下班后用刷手机兜底。

用户明确了一条立场：**溢出的时间成本由公司承担，不由个人吸收**。所以产品不是自律打卡器，而是**边界工具 + 证据生成器**：准时关门，并把"为什么没做完"变成一份可以拿出去的客观记录。

### 1.4 使用现状与设备拓扑（v0.3 新增）

| 项 | 现状 |
|---|---|
| **本职工作** | Claude Code + CC Switch + DeepSeek，**终端方式**；这是 90% 以上的 AI 消耗来源 |
| **DSH** | 尚不熟悉，仅用于探索与**本插件的开发**；自媒体相关将来可能迁入 |
| **工作设备** | 公司电脑（当前这台 Windows），受公司策略约束 |
| **个人设备** | 自己的 Mac 笔记本，用于自媒体 |
| **安装范围** | DSH 与核心工具在两台机器上都装 |

**这条事实直接决定了架构**：DSH 插件只能看见 DSH 内的消耗，而真实工作几乎全在 Claude Code 终端里。若把产品做成"一个 DSH 插件"，它记不到 90% 的账——**表盘做得再好，发动机没接上**。

## 2. 产品定位

**是什么**：本地优先的个人工具。一个**独立计量内核**藏在后面，前面挂三种壳：终端 CLI / Claude Code 状态栏 / DSH 面板。管一天的"工作预算""交付排期"和"个人时间"。

**不是什么**：不是 DSH 专属插件；不是团队效能工具；不是老板看板；不是通用时间追踪器；不是模型路由器；不是加班助手。

**成功的样子**：连续使用 4 周，Claude Code 状态栏每天都显示 `work 4.2/10`，周报能看到"本周为公司 22 小时 / 为自己 18 小时"，个人账号有可见产出，且至少有一次用溢出报告推动了范围或日期的调整。

## 3. 设计原则

| # | 原则 | 含义 | 反面案例 |
|---|---|---|---|
| P1 | **预算即硬顶** | 到 100% 立刻收工，没干完也停 | "就差一点，今天破个例" |
| P2 | **溢出归排期，不归人品** | 没干完是排期偏差，推动改范围或改日期 | 自责 → 偷偷加班 → 规则失效 |
| P3 | **日期是算出来的** | 先定预算与范围，日期是结果 | 先答应日期，再倒推加班 |
| P4 | **紧急通道必须昂贵且受限** | 二级上限有前置条件、配额、事后统计 | 每天都能"临时开一下" |
| P5 | **计量必须经得起自欺** | 数字来自日志与账单，不来自手填 | 手动"今天大概花了 8 块" |
| P6 | **空报告是合法输出** | 没有大事就说没有 | 每天硬凑 10 条"值得关注" |
| P7 | **账本按设备硬隔离** | 公司机永不写入个人账本内容 | 个人数据散落在公司机器上 |
| P8 | **分类由项目决定，不由设备决定** | 设备只是默认值，项目才是真相 | "在公司机上做的就是工作" |
| P9 | **终端优先** | 用户的工作流在终端里，状态栏比面板更常被看见 | 做一个必须切窗口才能看的仪表盘 |
| P10 | **收益框架优先** | 主视觉是"还剩多少自由时间"，不是"花了多少钱" | 每天一个红色超支数字 → 焦虑 → 弃用 |

## 4. 核心概念

| 术语 | 定义 |
|---|---|
| **日预算** | 默认 10 元。**硬性**：达到即收工，与交付是否完成无关 |
| **二级上限** | 默认 20 元，默认关闭。仅"赶交付"场景显式启用，有配额 |
| **账本（Ledger）** | `work` / `personal` 两个独立数据域，由设备决定，物理隔离 |
| **分类（Category）** | 账本内的子标签：`office` 本职 / `side` 个人项目 / `explore` 探索 / `tooling` 工具建设 |
| **归属判定链** | 显式标签 > 项目根标记 > 安装身份 > 未分类队列 |
| **元当量** | 把按量 / 订阅 / 赠送额度折算成人民币等值 |
| **时间当量** | 元 → 小时的换算率，默认 1 元 = 48 分钟（10 元 ≈ 8 小时），可配 |
| **交付项** | 含完成定义、预估成本、承诺日期的一条"今天必须产出什么" |
| **顺延（Carry）** | 未完成项移到次日队首，优先于新任务 |
| **溢出（Spill）** | 预算用尽但交付未完成，记录为排期偏差 |
| **溢出报告** | 客观记录：预算、已花、完成项、顺延项、预测日期 vs 承诺日期 |
| **排期** | 由"范围 ÷ 预算"推算的 P50 / P80 交付日 |
| **收尾豁免** | LOCKED 后仍允许提交/测试/写交接的独立额度（默认 0.5 元） |
| **收工凭证** | 公司机收工时生成的一行短码，在 Mac 上录入即开始个人时间块 |
| **个人时间块** | 收工后的受保护时段，必须绑定一个产出物 |

## 5. 部署形态与账本归属（v0.3 新增）

### 5.1 双机双账本

| | 公司笔记本 `work` | 个人 Mac `personal` |
|---|---|---|
| 主要负载 | Claude Code + CC Switch + DeepSeek；DSH（探索/插件开发） | DSH（主界面）、自媒体、资讯简报 |
| 账本 | 只此一本 | 只此一本 |
| 联网 | 默认关闭（除必要的价格表更新） | 允许 |
| 资讯抓取 | ❌ 不做 | ✅ 在这里做 |
| 面板 | CLI + Claude Code 状态栏为主，DSH 面板为辅 | DSH 面板为主 |

**硬边界**：公司机上不存在 `personal` 账本，Mac 上不存在 `work` 账本的内容。这不是技术限制，是隐私设计——公司机上的任何数据都要假设可能被审计。

### 5.2 分类与账本是两件事

这是 v0.3 最重要的澄清：

- **账本由设备决定（硬隔离）**：你在公司机做的任何事，数据都留在 work 账本里，不会流向 Mac；
- **分类由项目决定（软标签）**：公司机上的自媒体投入，记在 work 账本里打 `side` 标签。

为什么不用"用途"来分账本？因为一旦允许个人账本出现在公司机上，你就同时失去了合规性与隐私。宁可让 work 账本里混着 `side` 的记录，并在周报里单列一行"公司时间内的个人项目：6 小时 / 3.2 元"——**让自己看见，比藏起来更有效**。

### 5.3 归属判定链

| 优先级 | 信号 | 实现 | 稳定性 |
|---|---|---|---|
| 1 | 显式标签 | `/wb side`、面板开关、`--ledger` 参数 | 最高，但依赖人记得用 |
| 2 | 项目根标记 | 仓库根 `.workbudget.toml` 写 `category = "side"` | **最接近真相**：内容归属由项目决定 |
| 3 | 安装身份 | 首次启动时声明 `work` / `personal` | 默认值，足够覆盖 80% |
| 4 | 未分类队列 | 收工时 10 秒认领 | 兜底，防止账本腐化 |

**明确不做设备指纹识别**：既是出于隐私，也是因为它不可靠——你会用公司机做自媒体，也会用 Mac 回工作消息。

### 5.4 架构

```
 公司笔记本 [work]                          个人 Mac [personal]
 ┌────────────────────────────┐            ┌────────────────────────────┐
 │ Claude Code (终端)         │            │ DSH (主界面)               │
 │  ├ UserPromptSubmit hook ─┐│            │  ├ 插件面板 ────────────┐  │
 │  ├ PreToolUse hook ───────┤│            │  ├ 工具拦截 ────────────┤  │
 │  └ 会话日志 *.jsonl ──────┤│            │  └ 会话数据 ────────────┤  │
 │ CC Switch (只切 base_url)  │            │ 资讯抓取 / 简报          │  │
 │ DSH（探索/插件开发）───────┤│            │ 自媒体时间块             │  │
 │                            ↓│            │                          ↓  │
 │                    采集器 + 策略引擎      │                    采集器 + 策略引擎
 │                            ↓│            │                          ↓  │
 │                       账本 work           │                       账本 personal
 │         CLI / 状态栏 / DSH 面板           │         DSH 面板 / CLI     │
 └──────────────┬─────────────┘            └──────────────┬─────────────┘
                │       日汇总（可选 / 加密 / 默认关）     │
                └──────────────→ 周报合并 ←───────────────┘
```

**关键判断**：CC Switch 只负责切 `base_url`，**不影响记账**——只要流量仍走 Claude Code，hook 与日志就够用，不需要抓包代理，也不需要管理员权限。代理只在将来要覆盖"非 Claude Code 的 API 流量"时才需要。

### 5.5 跨机交接（刻意保持笨拙）

自动化互联的隐私成本太高，所以只做最小交接：

1. 公司机收工 → 终端打印一行 **收工凭证**（6 位码 + 当日摘要）；
2. 到 Mac 上输入该码 → 开启个人时间块，并把当日 work 摘要并入周报；
3. 周报合并只走**汇总数据**（金额、时长、条数），不走内容。

**隐私红线**（写进产品说明）：

- 不在公司机登录个人云盘 / 个人 GitHub 做同步；
- 不在公司机抓取资讯、不缓存个人账号内容；
- 公司机上的核心工具必须"可解释、可一键停用"：一个 CLI + 一段 hook 配置，无驱动、无后台常驻监听、无需管理员权限。

## 6. 剧本

### 6.1 顺利的一天（公司机）

| 时间 | 事件 | 系统行为 |
|---|---|---|
| 08:30 | 看简报 | 在 Mac 上 2 分钟看完；不计入工作预算 |
| 08:40 | 开工 | 登记 1–3 条交付项 + 预估；预算 10 元 |
| 11:30 | 预算到 70% | 状态栏变黄，提示砍范围 |
| 12:10 | 交付全完成，已花 4.2 元 | DONE：打印收工凭证，"为自己争取 5 小时 50 分" |
| 12:20 | Mac 上录码 | 开启个人时间块，锁 4 小时 |
| 18:00 | 日报 | 花了多少 / 交付了什么 / 省下多少 / 明天第一件事 |

### 6.2 用尽的一天（公司机）

| 时间 | 事件 | 系统行为 |
|---|---|---|
| 09:00 | 开工 | 3 条交付项，预估合计 14 元 → 提示"可能顺延 1 项" |
| 15:40 | 预算到 90% | WINDDOWN：不再开新任务 |
| 16:20 | 预算到 100% | **LOCKED**：公司账本关闭，只剩收尾豁免 |
| 16:25 | 收尾 | 提交、测试、写交接摘要，消耗 0.3 元 |
| 16:35 | 自动结算 | 溢出报告：完成 2/3，顺延 1 项，预测 11-06，承诺 11-05 |
| 16:40 | 收工 | 只显示"明天第一件事"和"今天到这里" |

> LOCKED 之后界面上**不存在"继续对话"的入口**，只有"申请二级上限"（条件不满足时置灰并说明原因）。

## 7. 功能需求

### FR-0 归属与账本路由（P0）

- **FR-0.1** 首次启动声明身份（`work` / `personal`），写入本地配置；**不做设备指纹**。
- **FR-0.2** 项目级覆盖：项目根 `.workbudget.toml` 的 `category` 字段优先于安装身份。
- **FR-0.3** 会话级覆盖：`/wb side`、`--category` 参数或面板开关，优先级最高，仅本次会话。
- **FR-0.4** 未判定条目进入"未分类"队列，收工时 10 秒认领；连续 3 天未认领给出提示。
- **FR-0.5** 每条 `usage_event` 记录 `ledger_id` + `category` + `attribution_source`，全程可审计。
- **FR-0.6** 公司机配置层面禁止创建 `personal` 账本（编译期/配置期双重限制，不是 UI 隐藏）。

### FR-1 计量与归集（P0）

- **FR-1.1** **Claude Code 适配器（首要）**：解析 `~/.claude/projects/**.jsonl`，按消息提取 `input` / `cache_read` / `cache_write` / `output` token。
- **FR-1.2** **DSH 适配器**：读取会话数据中的用量字段。
- **FR-1.3** 本地价格表按模型分四档，支持生效日期版本化；缓存命中与未命中必须分开计价。
- **FR-1.4** 归集：请求级事件 → 会话 → 日账；支持按项目打标签。
- **FR-1.5** 去重：同一请求被多个来源捕获时按 request id 合并。
- **FR-1.6** 对账：月度与厂商账单比对，偏差 > 5% 提示价格表过期。
- **FR-1.7** 口径声明：宿主提供的成本字段为估算值，一律以本地价格表重算为准，两套数字都保留。
- **FR-1.8**（P2）通用代理适配器：覆盖非 Claude Code 的 API 流量。

### FR-2 硬上限与二级上限（P0）

- **FR-2.1** 日预算默认 10 元，可配；工作日 / 周末可不同；改当天预算需二次确认并记入变更日志。
- **FR-2.2** 达到 100% 立即 `LOCKED`，禁止新任务，无论交付是否完成。
- **FR-2.3** 收尾豁免：LOCKED 后仍可提交、测试、写交接摘要，独立额度默认 0.5 元；用尽后只允许零 token 本地操作。
- **FR-2.4** 状态机：`NORMAL(0–70) → WARN(70–90) → WINDDOWN(90–100) → LOCKED(100)`。
- **FR-2.5** 执行点按宿主分别实现：Claude Code 用 `UserPromptSubmit` / `PreToolUse` hook 阻断；DSH 用工具中间件；代理场景返回 4xx。
- **FR-2.6** 预算分池（P1，可关）：生产 8 元 + 探索 2 元，探索池月底清零。
- **FR-2.7** **不借贷、不预支**：今日额度不可从明日借用或提前消耗。
- **FR-2.8** 二级上限默认 20 元、默认关闭；启用后当日上限切 20，18 元告警、20 元锁定。
- **FR-2.9** 启用前置条件（满足其一，否则置灰并说明）：距承诺日 ≤ 2 天且剩余工作量 > 1 个标准日；或交付方书面要求提前（需粘贴原文）。
- **FR-2.10** 启用需二次确认 + 一句理由 + 释放天数；全部记入 `tier2_use`。
- **FR-2.11** 配额：每月最多 4 次；第 3 次起启用前强制展示本月启用次数。
- **FR-2.12** 二级上限用尽仍未完成 → `SPILL_HARD`，作为排期失效的最强证据写入溢出报告首行。
- **FR-2.13** 周报统计：本月启用次数、避免的延期天数、启用后仍溢出的次数。

### FR-3 终端体验（P0）

- **FR-3.1** `wb` CLI：`status` / `log` / `task` / `done` / `spill` / `report` / `tier2`。
- **FR-3.2** **Claude Code 状态栏集成**：常驻显示 `work 4.2/10`，超 70% 变黄、超 90% 变红。这是最高频的界面，优先级高于任何面板。
- **FR-3.3** hook 输出必须是一句话、可执行（"还剩 1.2 元，建议只做收尾"），不刷屏。
- **FR-3.4** 收工时打印收工凭证与当日摘要，可复制。
- **FR-3.5** 所有写操作幂等：重复执行不产生重复记录。

### FR-4 排期与交付日期（P0）

- **FR-4.1** 任务录入：标题、完成定义、预估成本、依赖、期望交付日、优先级、分类。
- **FR-4.2** 排期计算：按日预算与近 4 周实际吞吐推算 `P50` / `P80` 完成日。
- **FR-4.3** 若 `P80 > 期望日`，标记不可行，给三个杠杆：加预算 / 减范围 / 改日期。
- **FR-4.4** 承诺日由用户确认后锁定；变更记录"谁改、为什么、对预算的影响"。
- **FR-4.5** 每日收工更新预测；`预测日 > 承诺日` 当天预警，不等到期。
- **FR-4.6** 预估偏差学习：对比预估与实际，滚动提示"你的预估通常偏低 30%"。

### FR-5 交付闸门与顺延（P0）

- **FR-5.1** 开工前登记 1–3 条交付项，每条有可验证的完成定义。
- **FR-5.2** `DONE` = 全部完成 ∧ 已花 ≤ 预算（含豁免额度）。
- **FR-5.3** 未完成项自动顺延到次日**队首**。
- **FR-5.4** 积压闸门：顺延工作量 > 2 个标准日时，开工前强制"重谈"（范围/日期/预算三选一）。
- **FR-5.5** 顺延只记为排期偏差，不扣分、不显示"连续失败天数"。

### FR-6 溢出报告（P0）

- **FR-6.1** 每次 `SPILL` / `SPILL_HARD` 自动生成记录：预算、实际花费、完成项、顺延项、预测日、承诺日、是否用二级上限。
- **FR-6.2** 一键生成"对外三句话"：当前进度 / 按此速度的预计日期 / 需要调整的一项。
- **FR-6.3** 可导出 Markdown 或复制到剪贴板。
- **FR-6.4** 周报汇总：溢出天数、累计延迟、二级上限次数。
- **FR-6.5** 文案基调为**陈述而非申诉**：只给数据和建议。

### FR-7 结余与再投资（P0）

- **FR-7.1** 结余**不结转成额度**（避免攒额度后报复性使用），只兑换为时间。
- **FR-7.2** `结余时间 = (预算 − 实际花费) × 时间当量`，默认 1 元 = 48 分钟。
- **FR-7.3** 记录墙钟：开工 / 收工；`今日收益 = 标准工作日 − 实际墙钟`。
- **FR-7.4** `DONE` 时展示"为自己争取 X 小时 Y 分"，并生成收工凭证。
- **FR-7.5** 个人时间块默认 4 小时，导出 ICS 写入日历，开始前 5 分钟提醒。
- **FR-7.6** 自己账本记录时间块 + 产出物（不必发布但必须存在）。
- **FR-7.7** 防蒸发：开始后 15 分钟未启动标记"未使用"；连续 3 天未使用给出提示。
- **FR-7.8** 周视图：公司 vs 自己 的时间与金额对比、本周多出几个半天。

### FR-8 资讯简报（P1，仅 personal 侧）

- **FR-8.1** 关注对象可配：默认 DeepSeek、OpenAI Codex、Claude Code、CC Switch；可加任意 GitHub 仓库 / RSS。
- **FR-8.2** 来源优先级：官方 changelog 与 release notes > GitHub Releases > 官方博客 > HN / X > 中文媒体。
- **FR-8.3** 分级：`P0 必须知道`（模型发布、价格与计费变更、破坏性变更、安全通告、major release）/ `P1` / 噪音丢弃。
- **FR-8.4** 长度硬约束：≤ 5 条、≤ 300 字、≤ 2 分钟；每条必须有"这跟你有什么关系"。
- **FR-8.5** 空报告合法：无 P0 时输出"今天没有值得你花时间的事"，条数为 0，不通知。
- **FR-8.6** 推送：每日固定一次（默认 08:30）+ P0 即时告警（每小时聚合，每天最多 1 条）。
- **FR-8.7** 去重：同一事件多源出现时按事件聚类。
- **FR-8.8** 资讯时间不计入工作预算，计入自己账本。

### FR-9 面板与复盘（P1）

- **FR-9.1** DSH 面板：剩余自由时间（大）、已用预算（小）、交付进度、状态、距承诺日天数。
- **FR-9.2** 日报：已花 / 交付 / 结余 / 顺延 / 明日第一件事。
- **FR-9.3** 周报：预算达成率、溢出天数、二级上限次数、自己账本时长、资讯命中率。
- **FR-9.4** 导出：CSV / JSON / Markdown。

### FR-10 配置与扩展（P2）

- 配置项覆盖预算、二级上限、配额、时间当量、豁免额度、分池、资讯源、个人块时长。
- 价格表手动更新 + 可选在线更新（默认关闭）。
- 对外只读数据接口。

## 8. 状态机

### 8.1 预算状态

| 状态 | 触发 | 允许的动作 | 提示 |
|---|---|---|---|
| `NORMAL` | < 70% | 全部 | 无 |
| `WARN` | 70–90% | 全部，新任务需确认预估 | "还剩 X 元，建议先砍范围" |
| `WINDDOWN` | 90–100% | 仅收尾与已开任务修补 | "进入收尾，不再开新任务" |
| `LOCKED` | ≥ 100% | 收尾（豁免 0.5 元）+ 二级上限入口 | "今天的额度用完了" |
| `TIER2` | 已启用二级，10–90% | 全部 | "二级上限已启用，剩余 X 元" |
| `TIER2_WARN` | 二级下 ≥ 90% | 仅收尾与修补 | "二级上限快用完了" |
| `TIER2_LOCKED` | 二级下 ≥ 100% | 仅收尾 | "二级上限也用完了" |
| `DONE` | 交付全完成 ∧ ≤ 预算 | 收工，开个人时间 | "你为自己争取了 X" |
| `SPILL` | 预算用尽 ∧ 未完成 | 收工，生成溢出报告 | "剩下的顺延到明天" |
| `SPILL_HARD` | 二级用尽 ∧ 未完成 | 收工，生成强证据报告 | "已动用二级上限仍未完成" |

### 8.2 预算 × 交付

| 预算 \ 交付 | 未完成 | 全部完成 |
|---|---|---|
| < 上限 | 继续工作 | **DONE**：收工，收益入账 |
| ≥ 上限 | **SPILL**：收工 + 报告 + 顺延 | 收工，收益为 0 |

**两种收工都是正常收工**，区别只在结算方式。

## 10. 非功能需求

| # | 要求 |
|---|---|
| NFR-1 | **双平台为一等公民**：Windows（公司机）与 macOS（个人机）在 M1 即需跑通，不接受"先 Windows 后移植" |
| NFR-2 | **零管理员权限**：不装驱动、不装服务、不监听端口；只有 CLI 二进制 + 用户级配置 + 一个数据目录 |
| NFR-3 | **可一键停用**：摘除 hook 配置即恢复原状，不留后台进程 |
| NFR-4 | **本地优先**：账本与日志留存本机；公司机默认零联网 |
| NFR-5 | **离线可用**：断网时计量、硬顶、排期、溢出报告全部正常 |
| NFR-6 | **低开销**：hook 执行 < 100ms，不拖慢每次提交；状态栏刷新不影响输入 |
| NFR-7 | **可审计**：每条成本可追溯到请求与计价规则；每次二级上限可追溯到理由与前置条件 |
| NFR-8 | **可恢复**：账本可由 usage_event 重放重建；每日自动备份 |
| NFR-9 | **可卸载干净**：无残留进程与定时任务，历史账本保留在用户目录 |

## 11. 边界与非目标

- ❌ 不做团队版、管理者视图、排行榜
- ❌ 不做设备指纹、不做窗口标题/键鼠/截屏采集
- ❌ 不做模型路由 / 自动选便宜模型
- ❌ 不做"道德记账"：不统计加班、不鼓励延长工时、没有"再干一小时"按钮
- ❌ 不做游戏化（积分、徽章、连续打卡）
- ❌ 不为跨机同步把两台电脑长期互联；同步只走日汇总，默认关闭
- ❌ 不在公司机上抓取资讯或登录个人账号

系统永远不建议"多干一会儿"，只会建议加预算、减范围、改日期——而加预算要动二级上限，要理由，要配额。

## 12. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| **只做 DSH 插件，覆盖不到真实负载** | 面板很漂亮，但 90% 的 Claude Code 花费记不到 | 内核独立 + Claude Code 适配器优先；DSH 面板作展示层 |
| **顺延积压螺旋** | 每天欠一项，一周后规则悄悄失效 | 积压闸门、每日更新预测、提前预警 |
| **二级上限滑坡** | "今天有点赶" → 天天启用 | 前置条件 + 配额 + 统计 + 置灰 |
| **双机账本分裂** | 周报只有半天数据 | 收工凭证 + 日汇总合并；日报允许缺半 |
| **公司机合规** | IT 策略禁止第三方常驻程序 | 零权限、无监听、可一键停用、源码可审 |
| **个人数据误落公司机** | 自媒体素材/账号出现在公司设备 | 账本硬隔离、公司机禁建 personal 账本、禁个人云盘同步 |
| **硬停留半成品** | 停在工作树中间，次日恢复成本高 | 收尾豁免、自动交接摘要、禁止硬杀进程 |
| 成本估算失真 | 与账单偏差大，不信任数字 | 双轨记录、月度对账、超阈值告警 |
| 混合计费击穿口径 | 订阅制边际成本≈0 | 元当量 + 影子价格 |
| 预算掐死探索 | 不敢发散尝试 | 探索池独立、月底清零 |
| 变成焦虑源 | 每天盯红色数字，两周弃用 | 收益框架、周维度、溢出不惩罚 |
| 用户开始骗系统 | 换工具绕开、手改数 | 计量自动化；绕行行为在周报提示但不指责 |

## 13. 验收标准

- **AC-1** 给定日预算 10 元、完成 2/3 交付项，花费达 10 元时立即 LOCKED，禁止新任务，生成溢出报告，剩余 1 项顺延次日队首。
- **AC-2** 二级上限未启用时，界面**不存在**任何"继续工作"入口（收尾豁免除外）。
- **AC-3** 启用条件不满足时，"申请二级上限"置灰并显示缺少哪个条件。
- **AC-4** 给定 3 个任务共 22 元预估、日预算 10 元，排期输出 P50 = 第 3 个工作日、P80 = 第 4 个；期望日为第 2 日时标记不可行并给三杠杆。
- **AC-5** 顺延工作量 > 2 个标准日时，开工前强制"重谈"，未处理则次日再现。
- **AC-6** Claude Code 状态栏常驻显示 `work X/10`，70% 与 90% 处颜色变化；hook 拦截时输出单行可执行建议。
- **AC-7** 公司机上执行 `/wb personal` 被拒绝，并提示"本机只运行 work 账本"。
- **AC-8** 在 Mac 录入公司机的收工凭证后，个人时间块开启，且周报出现当日 work 汇总。
- **AC-9** 给定关注源无 P0 事件，简报输出"今天没有值得你花时间的事"，条数为 0，不通知。
- **AC-10** 断网时计量、硬顶、排期、溢出报告正常；简报显示"稍后重试"且不丢事件。
- **AC-11** 卸载后无残留进程与定时任务，hook 配置已摘除，历史账本保留。
- **AC-12** 同一份账本在 Windows 与 macOS 上输出一致（时间当量、四舍五入、时区处理）。

## 15. 待确认问题

1. **公司机是否允许装 hook / CLI**：有没有 DLP、应用白名单、管理员限制？这决定公司机是"完整方案"还是"只能手动记录"。
2. **插件开发本身算哪一类**：算 `office`、`side`，还是单列 `tooling`？我倾向单列——它既不是本职交付，也不完全是自媒体，单列后在周报里看得见，不用假装它不存在。
3. **`side` 是否占用 10 元预算**：我的建议是**不占**（10 元是"公司时间"的上限，个人项目不吃它），但要单独统计并显著展示"今天在公司时间内做了 X 元个人项目"，避免自欺。这一条是价值观选择，需要你拍。
4. **时间当量**：默认 1 元 = 48 分钟（10 元 ≈ 8 小时）。你实际是几小时？这决定"半天"到底是 5 元还是别的数。
5. **二级上限参数**：20 元是否固定？每月 4 次是否合适？当天临时开还是至少提前一天申请？
6. **承诺日谁定**：你单方面定，还是要和上级/客户对齐？若要对齐，溢出报告是否需要"对外话术"模板？
7. **跨机同步**：手动录凭证就够，还是希望自动同步日汇总（意味着要搭一个私有同步点）？
8. **个人账本产出物**：自媒体具体形态（视频 / 图文 / 代码项目）？要不要记录发布数据？

# 安装 / 卸载 / 回滚

> 适用版本：Workday Budget v1.1.1（2026-11-04）
> 当前用户：`Administrator`
> 工作区：`E:\AI\workday-budget`

## 0. 当前安装形态

| 部件 | 位置 |
|---|---|
| wb 核心 | `core\wb.mjs` + `wb.cmd`（npm bin：`wb`） |
| DSH 插件 | 包根目录，以 `link:` 或 npm 包 `workday-budget` 装入 `desktop` profile |
| 插件入口 | `workday-budget`（DSH 左栏「预算」） |
| 数据目录 | `%APPDATA%\workbuddy` |
| Claude Code hooks | `%USERPROFILE%\.claude\settings.json` |
| 状态栏组件 | `%USERPROFILE%\.config\ccstatusline\settings.json` 的 custom-command |
| 开机自启 | `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\workday-budget-watch.vbs` |
| watcher | `wb watch`，当前由 Startup VBS 的 watchdog 启动 |

## 1. 安装

### 1.1 前置

- Node.js 24+（`wb.cmd` 会自动查找；当前机器为 mise Node 24.20.0）
- `npm install -g workday-budget`（或使用本地 `core\wb.cmd`）
- Claude Code 已安装，存在 `~/.claude/projects`
- 可选：`ccstatusline-zh` 已作为 Claude Code 的 statusLine；没有它时不要执行 `wb statusline install`
- DSH desktop 已存在 `desktop` profile

### 1.2 安装 DSH 插件

从 npm 安装：

```text
workday-budget@1.1.1
```

本地开发安装：

```text
link:E:/AI/workday-budget
```

等价的 profile 配置（`%USERPROFILE%\.dsh\profiles\desktop\package.json`）：

```json
"dependencies": {
  "workday-budget": "link:E:/AI/workday-budget"
},
"dsh": {
  "profile": {
    "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "workday-budget"]
  }
}
```

安装后刷新 DSH，左栏出现「预算」。

### 1.3 安装 Claude Code hooks

```powershell
cd core
.\wb.cmd hooks install
.\wb.cmd hooks status
```

`hooks install` 会先备份 `~/.claude/settings.json` 到 `%APPDATA%\workbuddy\settings-backup-*.json`，只添加：

- `UserPromptSubmit` → `wb.mjs check --hook`
- `PreToolUse` → `wb.mjs check --hook`

不会改 `env`、`theme`、`statusLine`。

### 1.4 合并状态栏（可选）

```powershell
.\wb.cmd statusline install
.\wb.cmd statusline status
```

它只在现有 `ccstatusline` 配置里加一个 `custom-command`，运行 `wb statusline --color`；不替换原 statusLine。

### 1.5 启动 watcher / 开机自启

手动：

```powershell
.\wb.cmd watch
.\wb.cmd watch --status
```

当前用户登录自启（可选，不需要管理员）：

```powershell
.\wb.cmd autostart install
.\wb.cmd autostart status
```

自启 VBS 会在登录时启动 `wb watch`；watchdog 在 watcher 崩溃后 5 秒重启。`autostart install` 只写当前用户 Startup，不动系统服务。

### 1.6 安装后验证

```powershell
.\wb.cmd doctor
.\wb.cmd selftest
cd ..\tests
.\run-tests.cmd
```

DSH 页面：

```powershell
Invoke-RestMethod http://127.0.0.1:57457/workday-budget/summary
```

预期：

- `doctor` 里 hooks 全 true，watch running，startup installed；
- `selftest PASS`；
- `run-tests.cmd` 32/32；
- summary 返回 `work/tooling/time/ledger`；
- 左栏「预算」可打开。

## 2. 卸载

按顺序执行，先停后台，再拆 hook/statusline，最后移除插件。

### 2.1 停 watcher / 自启

```powershell
cd core
.\wb.cmd autostart uninstall   # 停 watcher、删 Startup VBS
.\wb.cmd watch --stop          # 兜底，确保没有残留
.\wb.cmd watch --status        # 应为 running:false
```

`autostart uninstall` 会写 `watch.stop`，watchdog 退出，不会重启。

### 2.2 卸载 hooks

```powershell
.\wb.cmd hooks uninstall
.\wb.cmd hooks status
```

预期：`prompt=false`、`tools=false`；`statusLine`/`env` 原样保留。安装时的备份在 `%APPDATA%\workbuddy\settings-backup-*.json`。

### 2.3 卸载状态栏组件

```powershell
.\wb.cmd statusline uninstall
.\wb.cmd statusline status
```

预期：`merged=false`，原 ccstatusline 组件仍在。安装时备份在 `%APPDATA%\workbuddy\ccstatusline-backup-*.json`。

### 2.4 移除 DSH 插件

在 DSH 插件管理里移除 `workday-budget`，或：

```text
remove bundle workday-budget
```

验证：

```powershell
Invoke-WebRequest http://127.0.0.1:57457/workday-budget/summary
```

预期：404，侧栏「预算」消失。

### 2.5 数据保留

默认**保留** `%APPDATA%\workbuddy`：

- `usage-log.jsonl`（历史事件账本）
- `config.json` / `state.json`
- `time-log.jsonl` / `budget-log.jsonl` / `config-changes.jsonl`
- 备份文件

如确实要删除，先复制 `usage-log.jsonl` 和 `config.json`；删除后无法从 ledger 恢复历史。

## 3. 回滚

### 3.1 插件回滚/重装

```text
link:E:/AI/workday-budget
```

或恢复 `%USERPROFILE%\.dsh\profiles\desktop\package.json.t04-backup` 后重装依赖。

验证：`/workday-budget/summary` 返回 200。

### 3.2 hooks 回滚

优先用安装备份：

```powershell
Copy-Item "$env:APPDATA\workbuddy\t04-settings-backup.json" "$env:USERPROFILE\.claude\settings.json" -Force
```

或重新安装：

```powershell
.\wb.cmd hooks install
.\wb.cmd hooks status
```

备份文件包含 `env`（可能含 token），不要提交、不要打印内容。

### 3.3 状态栏回滚

```powershell
Copy-Item "$env:APPDATA\workbuddy\t04-ccstatusline-backup.json" "$env:USERPROFILE\.config\ccstatusline\settings.json" -Force
```

或重装组件：

```powershell
.\wb.cmd statusline install
```

### 3.4 配置/状态回滚

配置：

```powershell
Copy-Item "$env:APPDATA\workbuddy\config.json.bak-<时间戳>" "$env:APPDATA\workbuddy\config.json" -Force
```

状态：

```powershell
.\wb.cmd rebuild            # 从 usage-log.jsonl 恢复 state
.\wb.cmd rebuild --source   # ledger 也损坏时，从原始日志重建
```

不要用测试遗留的 `state-before-t02-test.json` / `state-t02-test-backup.json` 覆盖真实状态，除非明确知道要回到哪一天。

### 3.5 重启 watcher/自启

```powershell
.\wb.cmd autostart install
```

或手动：

```powershell
Start-Process -FilePath "wscript.exe" -ArgumentList "`"$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup\workday-budget-watch.vbs`""
.\wb.cmd watch --status
```

### 3.6 回滚后验证

```powershell
.\wb.cmd doctor
.\wb.cmd selftest
```

并检查：

- hooks `prompt/tools=true`
- statusline `merged=true`
- `/workday-budget/summary` 200
- watcher `running=true`
- `state.json` 的 `date/work.spent` 合理

## 4. 故障恢复

| 现象 | 处理 |
|---|---|
| watcher 不运行 | `wb watch --status`；`wb autostart install` 后重启 VBS |
| PID 被别的进程复用 | `wb watch --stop` 会校验命令行，不会误杀 |
| 状态栏显示旧值 | `wb statusline`；检查 `watch --status` 的 lastTick |
| state 损坏 | `wb rebuild`；再不行 `wb rebuild --source` |
| hooks 后 Claude Code 被误拦 | `wb hooks uninstall`，检查 `~/.claude/settings.json` |
| 插件卸载后 404 | 重新安装 link bundle |
| 自启重复 | 只保留一个 Startup VBS；`wb autostart uninstall` 再 install |

## 5. 备份清单

| 文件 | 来源 |
|---|---|
| `settings-backup-*.json` | `wb hooks install` |
| `ccstatusline-backup-*.json` | `wb statusline install` |
| `config.json.bak-*` | 面板/设置写入 |
| `t04-settings-backup.json` | T04 真机卸载测试前 |
| `t04-ccstatusline-backup.json` | T04 状态栏测试前 |
| `package.json.t04-backup` 等 | T04 插件卸载测试前 profile |
| `state-t02-test-backup.json` | T02 测试前状态 |

> `settings-backup`/`t04-settings-backup` 含 Claude Code 环境变量，按敏感文件处理。

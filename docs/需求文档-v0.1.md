# 工作日预算器（Workday Budget）

> 需求文档 v0.1 · 讨论稿 · 2026-11-03
> 代号建议：**十块下班**

---

## 0. 一页纸摘要

把「今天的工作」当成一笔**有上限的预算**来经营：花完就收工，提前干完就提前收工，省下的时间**强制转投**到自己的事业上。

产品由三个环组成：

1. **计量环**：把 AI 编程的消耗折算成钱，逐日累计；
2. **封顶环**：接近/超过上限时，从"提醒"升级到"只允许收尾"，再到"必须借款才能继续"；
3. **再投资环**：当日交付完成即判定"今天的工作结束了"，剩余时间进入受保护的个人时间块，并单独记账。

附带一个**资讯简报**：每天 2 分钟，回答"今天有没有必须知道的事"，没有就明确说没有。

一句话价值：**让时间有价格，让结余有去处。**

---

## 1. 背景与问题

### 1.1 三个场景

| # | 场景 | 用户原话（意译） |
|---|---|---|
| S1 | AI 编程限额 | 一天用在 AI 编程上的钱最多 10 块，超过必须停止工作；上限可配 |
| S2 | AI 资讯 | 每天要知道有没有大事，尤其 Codex / Claude Code / DeepSeek / CC Switch；关注对象可指定 |
| S3 | 时间再投资 | 半天干完就算一天干完，省下的半天投给自己的自媒体，而不是公司 |

### 1.2 共同结构

三个场景表面无关，结构完全一致：**给一类稀缺资源划边界，再把边界内省下的容量转投到别处。**

| 场景 | 被约束的资源 | 边界 | 释放出的容量 | 去向 |
|---|---|---|---|---|
| S1 | AI 编程的消耗（钱） | 日预算 10 元 | 未花完的额度 | 结转 / 换一个攻坚日 |
| S2 | 信息焦虑（注意力） | 每天 2 分钟 | 不再漫无目的刷资讯的时间 | 回到工作或个人 |
| S3 | 工作时长 | 交付完成即结束 | 半天时间 | 个人事业 |

### 1.3 真正要解决的问题

不是"省钱"，也不是"看新闻"。是：**一天的时间没有标价，所以会被无意识地稀释**——上班时用加班兜底，下班后用刷手机兜底。

用户要的是一套**外部约束装置**：把"我应该少干点"这种靠意志力的自我要求，变成"系统不让我干了"的机制。

> 产品本质：一份**和自己签的注意力合同**，插件只是合同的执行器。

## 2. 产品定位

**是什么**：一个本地优先的个人工具，装在 AI 编程宿主里，管一天的"工作预算"和"个人时间"。

**不是什么**：不是团队效能工具，不是老板看板，不是通用时间追踪器，不是模型路由器。

**成功的样子**：连续使用 4 周后，用户能在周报里看到"本周为公司 22 小时 / 为自己 18 小时"，且个人账号有可见产出。

## 3. 设计原则

| # | 原则 | 含义 | 反面案例 |
|---|---|---|---|
| P1 | **预算只是上限，交付才决定结束** | 花钱少 ≠ 干完了；两个条件同时满足才算收工 | 花了 3 块但任务没动，就宣布下班 |
| P2 | **计量必须经得起自欺** | 数字来自日志与账单，不来自手动填写 | 手动"今天大概花了 8 块" |
| P3 | **约束要有弹性** | 允许借款、允许结转，但都有代价 | 一刀切锁死 → 第二天报复性使用 |
| P4 | **空报告是合法输出** | 没有大事就明确说没有，不凑数 | 每天硬凑 10 条"值得关注" |
| P5 | **本地优先，没有老板视图** | 数据不出本机，不做排名与考核 | 一旦感觉被监控，用户就开始骗系统 |
| P6 | **收益框架优先** | 主视觉是"今天还剩多少自由时间"，不是"你花了多少钱" | 每天一个红色超支数字 → 焦虑 → 弃用 |

## 4. 核心概念

| 术语 | 定义 |
|---|---|
| **工作日账本（Day Ledger）** | 一天一条记录：预算、已花、结余、借款、交付项、状态 |
| **元当量** | 把所有计费方式（按量 / 订阅 / 赠送额度）折算成人民币等值，用于和"10 元"比较；订阅部分标注"折算" |
| **交付项（Deliverable）** | 开工前写下的 1–3 条"今天必须产出什么"，每条含**完成定义**与预估成本 |
| **双账本** | 公司账本（有上限、可结转）+ 自己账本（有下限、受保护） |
| **借款（Borrow）** | 超额后继续工作的唯一通道，按 1.5 倍计入次日 |
| **结转（Rollover）** | 当日结余按比例转入次日，有上限 |
| **个人时间块（Self Block）** | 交付完成后自动开启的受保护时段，必须绑定一个产出物 |
| **收尾动作** | 提交、跑测试、写交接、存档；在超额状态下仍允许执行 |

## 5. 典型的一天

| 时间 | 事件 | 系统行为 |
|---|---|---|
| 08:25 | 晨报 | 2 分钟简报；**不计入工作预算** |
| 08:40 | 开工 | 写 1–3 条交付项 + 预估成本；预算 10 元 |
| 11:30 | 预算到 70% | 提示剩余额度与未完成项，建议砍范围 |
| 12:10 | 交付全部勾选，已花 4.2 元 | 判定 DONE："今天的工作结束了，你为自己争取了 5 小时 50 分" |
| 12:15 | 开启个人时间块 | 锁定 4 小时，填写今日产出物 |
| 16:30 | 个人块结束 | 归档产出物；可标记"已发布/草稿" |
| 18:00 | 日报 | 花了多少 / 交付了什么 / 省下多少 / 明天第一件事 |

**关键**：12:10 之后，公司账本关闭，任何"顺手再改一下"的请求都会被拦下并记入次日借款。

## 6. 功能需求

优先级：P0 = 没有它产品不成立；P1 = 首个可用版本；P2 = 后续增强。

### FR-1 计量与归集（P0）

- **FR-1.1** 读取宿主会话数据，按请求累计 token 用量：`input`、`cache_read`、`cache_write`、`output`。
- **FR-1.2** 本地价格表按模型分四档计价，支持生效日期版本化；缓存命中价与未命中价必须分开（两者可差一个数量级）。
- **FR-1.3** 归集粒度：请求级事件 → 会话 → 日账；支持按会话/项目打标签。
- **FR-1.4** 去重：同一请求同时被会话日志与代理捕获时，按 request id 合并。
- **FR-1.5** 对账：月度与厂商账单比对，偏差 > 5% 提示"价格表可能过期"。
- **FR-1.6** 明确计费口径：宿主提供的成本字段为**估算值**，一律以本地价格表重算为准，两套数字都保留以便审计。
- **FR-1.7**（P1）接入非宿主工具：解析 Claude Code / Codex 的本地会话日志；或经本地代理统一记账。

> 技术风险：宿主是否暴露逐请求用量与 request id，需要 M0 阶段验证。若只有会话级汇总，则降级为"会话级估算 + 日内按比例分配"，并在 UI 标注精度。

### FR-2 预算与封顶（P0）

- **FR-2.1** 日预算默认 10 元，可配置；支持工作日 / 周末不同值；支持临时改（改当天需二次确认）。
- **FR-2.2** 预算分池（可关闭）：生产池 8 元 + 探索池 2 元。探索池用于"想不清楚先试试"的高消耗探索，月底清零、鼓励当月用掉。
- **FR-2.3** 预算状态机：`NORMAL → WARN(70%) → WINDDOWN(90%) → LOCKED(100%)`。
- **FR-2.4** 超额执行点：
  - 软：面板横幅 + 系统提示注入（"请只做收尾"）；
  - 硬（P0）：拦截新的工具调用，仅放行收尾动作白名单；
  - 更硬（P2）：本地代理返回 402，覆盖宿主外的所有 CLI。
- **FR-2.5** 借款：LOCKED 后可借款，1.5 倍计入次日；单日借款上限 5 元；连续两天借款需填写原因。
- **FR-2.6** 结转：结余 50% 结转，账户上限 20 元；超额则清零结转。
- **FR-2.7** 不做硬杀进程：中断必须留下干净状态（未提交改动提示、交接摘要）。

### FR-3 交付闸门（P0）

- **FR-3.1** 开工前登记 1–3 条交付项，每条含"完成定义"（可验证的一句话）与预估成本。
- **FR-3.2** 收工逐条勾选；勾选可选附证据（commit hash / 文件路径 / 链接）。
- **FR-3.3** DONE 条件：**全部交付项完成 ∧ 已花 ≤ 预算**。
- **FR-3.4** 未完成处理：顺延到次日（占用次日预算的 30%）或标记放弃（需写一句原因）。
- **FR-3.5** 超额且未完成 → `OVERRUN`，记录为"超支日"，触发一次复盘提问（是估错了，还是卡住了？），但不惩罚。

### FR-4 结余与再投资（P0）

- **FR-4.1** DONE 后弹出"收工"卡片，主数字为**今日为自己争取的时间**（按当日实际工时推算）。
- **FR-4.2** 个人时间块默认 4 小时，可调；写入日历（ICS 导出）；开始前 5 分钟提醒。
- **FR-4.3** 自己账本：记录时间块 + 产出物（文章 / 视频脚本 / 代码 / 其他），产出物不必发布但必须存在。
- **FR-4.4** 防蒸发：时间块开始后 15 分钟未启动，标记"未使用"；连续 3 天未使用给出提示。
- **FR-4.5** 周视图：公司 vs 自己 的时间与金额对比，以及"本周多出几个半天"。

### FR-5 资讯简报（P1）

- **FR-5.1** 关注对象可配：默认 DeepSeek、OpenAI Codex、Claude Code、CC Switch；可加任意 GitHub 仓库 / RSS / 站点。
- **FR-5.2** 来源优先级：官方 changelog 与 release notes > GitHub Releases > 官方博客 > HN / X > 中文媒体。
- **FR-5.3** 分级：`P0 必须知道`（模型发布、价格与计费变更、破坏性变更、安全通告、关注仓库的 major release）/ `P1 值得知道` / 噪音丢弃。
- **FR-5.4** 长度硬约束：≤ 5 条、≤ 300 字、≤ 2 分钟；每条必须有一句"**这跟你有什么关系**"。
- **FR-5.5** 空报告合法：无 P0 事件时输出"今天没有值得你花时间的事"，不生成任何条目。
- **FR-5.6** 推送：每日固定时间一次（默认 08:30）+ P0 即时告警（每小时聚合，每天最多 1 条）。
- **FR-5.7** 去重：同一事件多源出现时按事件聚类，只保留一条并附多源链接。
- **FR-5.8** 资讯时间不计入工作预算，计入自己账本（认知投资）。

### FR-6 面板与复盘（P1）

- **FR-6.1** 主面板：今日剩余自由时间（大）、已用预算（小）、交付项进度、预算状态。
- **FR-6.2** 日报：已花 / 交付 / 结余 / 明日第一件事。
- **FR-6.3** 周报：预算达成率、超支天数、自己账本时长、资讯命中率（推了几条、点开几条、标"有用"几条）。
- **FR-6.4** 导出：CSV / JSON / Markdown 周报。

### FR-7 配置与扩展（P2）

- **FR-7.1** 配置项：预算、分池、借款倍率与上限、结转比例、资讯源、简报时间、个人块默认时长。
- **FR-7.2** 价格表手动更新 + 可选在线更新（默认关闭）。
- **FR-7.3** 对外提供只读数据接口，便于将来做移动端或自建看板。

## 7. 状态机

### 7.1 预算状态

| 状态 | 触发 | 允许的动作 | 系统提示 |
|---|---|---|---|
| `NORMAL` | 已花 < 70% | 全部 | 无 |
| `WARN` | 70%–90% | 全部，新任务需确认预估 | "还剩 X 元，建议先砍范围" |
| `WINDDOWN` | 90%–100% | 仅收尾动作 + 已完成任务的修补 | "进入收尾，不再开新任务" |
| `LOCKED` | ≥ 100% | 仅收尾动作；继续需借款 | "预算已用尽，借款按 1.5 倍计入明天" |

### 7.2 预算 × 交付 组合

| 预算 \ 交付 | 未完成 | 全部完成 |
|---|---|---|
| < 100% | 正常继续 | **DONE**：收工，开启个人时间，结余按比例结转 |
| ≥ 100% | **OVERRUN**：只允许收尾或借款，触发复盘 | **DONE-OVER**：收工，但不奖励，结余为负 |

**只有右下角那一格才是"赢"**——这是整个产品的价值观。

## 9. 非功能需求

| # | 要求 |
|---|---|
| NFR-1 | **本地优先**：所有账本与日志留存本机；网络仅用于资讯抓取；任何上传需显式开启 |
| NFR-2 | **离线可用**：断网时计量与封顶照常工作（本地价格表 + 本地账本），简报降级为"稍后重试" |
| NFR-3 | **低开销**：计量逻辑不影响正常对话延迟；面板渲染 < 100ms |
| NFR-4 | **可审计**：每条成本可追溯到具体请求与计价规则 |
| NFR-5 | **可恢复**：账本损坏可重建（由 usage_event 重放）；每日自动备份一份 |
| NFR-6 | **权限最小化**：插件只读会话数据与价格表，写操作限于自己的数据目录 |
| NFR-7 | **跨平台**：Windows / macOS 至少各跑通一次 |
| NFR-8 | **可卸载干净**：卸载后不留后台进程、不残留定时任务 |

## 10. 边界与非目标

- ❌ 不做团队版、不做管理者视图、不做排行榜
- ❌ 不记录窗口标题、键鼠活动、屏幕内容（这是监控软件的做法）
- ❌ 不做模型路由 / 自动选便宜模型（那是另一类产品，会让计量失去意义）
- ❌ 不强制发布自媒体内容，只保证"时间被用在产出物上"
- ❌ 不做"摸鱼检测"——计量的是**资源效率**，不是**逃避工作**

关于最后一条，需要写进产品说明：如果某个任务客观上需要三天，系统应该诚实地说"预算不够，要么加预算，要么改范围"，而不是逼用户假装完成。**压缩工时的正当性来自"同样产出用更少资源"，不来自"少干活"。**

## 11. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 成本估算失真 | 与账单偏差大，用户不信任数字 | 双轨记录（估算/账单）、月度对账、偏差超阈值告警 |
| 混合计费击穿口径 | 订阅制工具边际成本≈0，"10 元"无对应物 | 元当量 + 影子价格（订阅费 ÷ 周期额度 × 用量比例） |
| 预算掐死探索 | 不敢用 AI 做发散尝试，长期能力下降 | 探索池独立、月底清零、不占生产额度 |
| 超额中断留半成品 | 第二天恢复成本高于省下的钱 | WINDDOWN 预留 10% 给收尾；禁止硬杀；自动生成交接摘要 |
| 变成焦虑源 | 每天盯着红色数字，两周后弃用 | 收益框架主视觉、周维度看趋势、超支不惩罚只复盘 |
| 用户开始骗系统 | 手动改数、换工具绕开 | 计量自动化、绕开行为在周报里提示但不指责 |
| 资讯噪音反噬 | 推得多、看得少，重新变成刷信息 | 长度硬约束、空报告合法、命中率反馈闭环 |
| 隐私顾虑 | 担心账本被上传 | 本地优先、开源、可审计、默认零上传 |
| 宿主 API 不支持 | 拿不到逐请求用量或拦截不了工具 | M0 先做技术验证，降级路径提前设计 |

## 12. 验收标准

- **AC-1** 给定日预算 10 元、已消耗 9.6 元，当发起新的工具调用时，系统拒绝并提示"仅允许收尾操作"，且不中断当前已提交的改动。
- **AC-2** 给定 3 条交付项全部勾选、已花 4.2 元，系统判定 DONE，展示"今日为自己争取 5 小时 50 分"，并提示开启个人时间块。
- **AC-3** 给定关注源今日无 P0 事件，简报输出"今天没有值得你花时间的事"，条目数为 0，且不产生任何通知。
- **AC-4** 给定订阅制 provider，元当量折算与月度账单偏差 ≤ 5%。
- **AC-5** 断网状态下，计量、封顶、DONE 判定全部正常；简报显示"稍后重试"且不丢事件。
- **AC-6** 给定 LOCKED 状态借款 2 元，次日账本自动扣减 3 元，且借款记录可追溯。
- **AC-7** 卸载插件后，无残留进程、无残留定时任务，历史账本保留在用户数据目录。
- **AC-8** 任意一条成本数字，可在 2 次点击内追溯到具体请求与计价规则。

## 13. 里程碑

| 阶段 | 内容 | 预估 | 出口标准 |
|---|---|---|---|
